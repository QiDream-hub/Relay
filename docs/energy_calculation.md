# ToolShell 能量消耗计算

## 能量消耗组成

ToolShell 的能量消耗分为三部分：

### 1. 核心基础消耗（每 tick）
```
energyCostPerTick = baseEnergyCost × count^1.3
baseEnergyCost = 1.0 / interval
```
- **扣除时机**: 每 tick 只扣除一次（无论执行多少个操作）
- **count**: 运算核心物品堆叠数量（1-64）
- **interval**: 执行间隔（tick 数）

### 2. 操作基础消耗（每次操作）
```
operationEnergy = instruction.getEnergy()
```
- **扣除时机**: 每个操作执行时
- **典型值**: 0.05（基础操作如 Add/Dup），0.25（复杂操作如 Raycast）

### 3. 世界交互器额外消耗（每次需要世界交互的操作）
```
worldInteractorEnergy = sqrt(tier) × 0.5
```
- **扣除时机**: 每次调用 `OperationHelpers.checkWorldInteractor()` 时
- **tier**: 世界交互器品阶（1-64）

| COMPUTING_CORE_64 | 1 | 1.0 | 1.000 | 6.063 | 37.500 | 232.000 |

**公式**: `energyCostPerTick = (1.0 / interval) × count^1.3`

**示例计算** (COMPUTING_CORE_64, count=1):
```
baseEnergyCost = 1.0 / 1 = 1.0
energyCostPerTick = 1.0 × 1^1.3 = 1.0
```

**示例计算** (COMPUTING_CORE_64, count=64):
```
baseEnergyCost = 1.0 / 1 = 1.0
energyCostPerTick = 1.0 × 64^1.3 = 1.0 × 232.0 = 232.0
```

## 典型程序能量消耗估算

假设场景：
- 程序包含 10 个操作
- 50% 的操作需要世界交互器（5 个）
- 每 tick 执行 1 个操作（coreCount=1）
- 程序运行 10 tick 完成

### 场景 1: 低级配置
- **核心**: COMPUTING_CORE_1 (interval=64), count=1
- **世界交互器**: WORLD_INTERACTOR_1 (tier=1)
- **操作基础消耗**: 0.05/操作

**计算**:
```
核心基础消耗 = 0.0156 × 10 tick = 0.156
操作基础消耗 = 0.05 × 10 操作 = 0.5
世界交互器消耗 = 0.5 × 5 次 = 2.5
────────────────────────────────────
总消耗 = 3.156 能量
```

### 场景 2: 中级配置
- **核心**: COMPUTING_CORE_16 (interval=4), count=4
- **世界交互器**: WORLD_INTERACTOR_16 (tier=16)
- **操作基础消耗**: 0.05/操作

**计算**:
```
核心基础消耗 = 1.516 × 10 tick = 15.16
操作基础消耗 = 0.05 × 10 操作 = 0.5
世界交互器消耗 = 2.0 × 5 次 = 10.0
────────────────────────────────────
总消耗 = 25.66 能量
```

### 场景 3: 高级配置
- **核心**: COMPUTING_CORE_64 (interval=1), count=16
- **世界交互器**: WORLD_INTERACTOR_64 (tier=64)
- **操作基础消耗**: 0.25/操作（复杂操作如 Raycast）

**计算**:
```
核心基础消耗 = 37.5 × 10 tick = 375.0
操作基础消耗 = 0.25 × 10 操作 = 2.5
世界交互器消耗 = 4.0 × 5 次 = 20.0
────────────────────────────────────
总消耗 = 397.5 能量
```

## 能量消耗占比分析

### 场景 1（低级配置）
```
核心基础：0.156 (4.9%)
操作基础：0.5   (15.8%)
世界交互器：2.5   (79.3%)
```
**结论**: 低频运行时，世界交互器消耗占主导

### 场景 2（中级配置）
```
核心基础：15.16 (59.1%)
操作基础：0.5   (2.0%)
世界交互器：10.0  (39.0%)
```
**结论**: 中频运行时，核心基础消耗开始占主导

### 场景 3（高级配置）
```
核心基础：375.0 (94.3%)
操作基础：2.5   (0.6%)
世界交互器：20.0  (5.0%)
```
**结论**: 高频运行时，核心基础消耗占绝对主导

## 优化建议

1. **低频场景**（interval≥16）:
   - 优先升级世界交互器品阶
   - 核心堆叠数量影响较小

2. **中频场景**（interval=4-8）:
   - 平衡核心和世界交互器的升级
   - 注意核心堆叠的指数增长消耗

3. **高频场景**（interval=1-2）:
   - 核心基础消耗占主导
   - 谨慎使用高堆叠数量
   - 世界交互器消耗相对次要

4. **通用优化**:
   - 减少不必要的世界交互操作
   - 使用缓存避免重复查询
   - 合理设计程序减少操作数量
