# 《我的世界》模组概念设计文档

**致谢**：本模组的执行模型深受 [Hex Casting](https://github.com/FallingColors/HexCasting) 启发，在此向 Hex Casting 团队致敬。

---

## 一、核心设计理念

**玩家通过栈图编程，为工具/方块/实体编写自动化行为程序。**

- **操作是一级公民**：操作可被创建、组合、传递、动态执行
- **双栈执行模型**：程序栈存可执行单元，数据栈存临时值
- **无原生循环**：循环通过列表自引用 + `eval` 实现
- **永续运行**：程序加载后持续运行，直到程序栈为空或显式停止
- **操作数预算**：每 Tick 可执行的操作数由激活的核心数决定

---

## 二、物品清单

| 物品 | 作用 | 可变版本 | 必需 |
|------|------|----------|------|
| 运算核心 | 提供操作数预算，相邻合并增强算力 | ✅ | 是 |
| 法术磁盘 | 存储栈图程序（操作列表） | ✅ | 是 |
| 能量模块 | 存储紫水晶能量 | ❌ | 是 |
| 世界交互器 | 决定是否允许与世界交互（无则仅为超算） | ✅ | 否 |
| 外壳 | 容器，决定形态（方块/实体/工具） | ❌ | 是 |

**核心属性**：
- `interval`：每隔多少 Tick 执行一次会话（可变核心可调 1~100）
- 物理相邻的核心自动合并：总核心数累加，`interval = max(所有核心)`

## 三、类型系统（Iota）

| 类型 | 说明 | 示例 |
|------|------|------|
| 数值 | 整数或浮点数 | `10`、`3.14` |
| 布尔 | 真/假 | `true`、`false` |
| 向量 | 三维坐标 | `[100, 64, 200]` |
| 字符串 | 文本 | `"hello"` |
| 实体 | 实体 UUID | `entity(uuid)` |
| 列表 | 有序集合，可包含任意 Iota | `[1, "a", true]` |

不使用引用类型，所有间接引用通过**列表**实现。程序本身也是列表（操作序列的列表）。

## 四、执行模型

### 4.1 双栈结构

每个外壳拥有独立的状态机，维护两个栈：

| 栈 | 存放内容 | 操作 |
|----|----------|------|
| **程序栈** | 可执行单元（操作ID、列表） | 弹出顶部即执行 |
| **数据栈** | 临时值（数字、布尔、向量等） | 操作参数来源，返回值去向 |

### 4.2 程序加载

外壳激活时，从法术磁盘读取程序（一个 Iota 列表）。由于**栈的顶部优先执行**，为了保证程序的第一个操作最先执行，需要将程序列表**反转**后压入程序栈。

**示例**：
```
磁盘程序（从左到右执行）：[push(1), push(1), add]
反转后压入程序栈（底部 → 顶部）：[add, push(1), push(1)]
```
执行时，顶部 `push(1)` 最先弹出，符合预期顺序。

### 4.3 执行流程

每个 Tick，状态机执行以下循环：

```
剩余操作数 = 激活的核心数
while 剩余操作数 > 0 且 程序栈非空:
    top = 程序栈.pop()          # 弹出栈顶
    
    if top 是操作ID（字符串）:
        查找操作注册表，执行对应回调
        回调可能：
            - 从数据栈.pop() 获取参数
            - 向数据栈.push() 返回结果
            - 向程序栈.push() 压入新的可执行单元
    else if top 是列表:
        # 将列表中的元素反转后压入程序栈
        # 反转保证列表的第一个元素成为新栈顶，立即执行
        reversed = 反转(top.asList())
        for item in reversed:
            程序栈.push(item)
    else if top 是数据:
        # 宽容处理：自动压入数据栈，继续执行
        数据栈.push(top)
    
    剩余操作数 -= 1
```

### 4.4 程序生命周期

- **永续运行**：程序加载后持续跨 Tick 执行，直到程序栈为空。
- **程序栈空**：自然终止，不再执行任何操作（除非外部重新激活）。
- **停机操作**：`stop` 清空程序栈和数据栈，强制终止。
- **外壳的 `interval`**：每隔 `interval` Tick 执行一次上述循环，不影响栈状态（不重置）。

### 4.5 循环与控制流

- 无原生循环或跳转指令。
- 通过 `eval` 操作实现控制流：
  - `eval` 从数据栈弹出列表，将其反转后压入程序栈
  - 压入后，该列表的第一个操作立即成为栈顶，下次循环执行
- 循环通过“自复制”模式实现：
  ```lua
  loop_body = [ ...循环体..., push(loop_body), eval ]
  ```
- 条件分支：`if` 操作从数据栈弹出条件（布尔）和两个列表，根据条件将其中一个列表反转后压入程序栈。

### 4.6 示例：1+1 计算

**初始**（外壳加载时）：
```
磁盘程序：[push(1), push(1), add]
反转后压入程序栈：
程序栈（底→顶）：[add, push(1), push(1)]
数据栈：[]
```

**执行过程**（每步为一个循环）：

| 步骤 | 程序栈（底→顶） | 数据栈 | 操作 |
|------|----------------|--------|------|
| 初始 | `[add, push(1), push(1)]` | `[]` | 加载完成 |
| 第1步 | `[add, push(1)]` | `[1]` | 弹出 `push(1)`，压入数据 `1` |
| 第2步 | `[add]` | `[1, 1]` | 弹出 `push(1)`，压入数据 `1` |
| 第3步 | `[]` | `[2]` | 弹出 `add`，计算 1+1=2，压入结果 |
| 结束 | 程序栈空，终止 | `[2]` | 结果保留在数据栈 |

## 五、通信模型

### 5.1 基础操作

| 操作 | 说明 | 返回值 |
|------|------|--------|
| `send(channel, data)` | 发送数据到数字频道 | `boolean` |
| `recv(channel)` | 尝试接收数据 | `data` 或 `null` |
| `peek(channel)` | 窥探下一条数据（不移除） | `data` 或 `null` |

### 5.2 设计原则

- 非阻塞，无数据立即返回 `null`。
- 每次操作消耗 1 操作数（包括返回 `null`）。
- 频道用数字标识，公开资源，玩家自行约定。
- 支持跨维度通信。
- 单频道最大队列长度 1000，超出触发事故。

## 六、物理合并与超算

- 相邻核心自动合并：总核心数累加，`interval = max(所有核心)`。
- 操作数预算 = 激活的核心数（≤ 总核心数）。
- 无世界交互器的外壳可作为纯超算节点（所有世界交互操作触发事故）。

## 七、能量管理

| 规则 | 说明 |
|------|------|
| 能量来源 | 紫水晶碎片(25)、紫水晶块(250) |
| 读取顺序 | 优先能量模块，其次背包紫水晶 |
| 预检 | 能量不足时跳过整个 batch |
| 操作执行时能量不足 | 触发事故，终止程序 |

## 八、错误处理

### 核心原则

**唯一宽容规则**：程序栈弹出数据 → 自动压入数据栈

**其他所有异常**：触发事故 → 清空双栈 → 停止运行

### 错误处理完整表格

| 情况 | 行为 | 是否继续 |
|------|------|----------|
| 程序栈弹出**数据**（数字、布尔、向量、字符串、实体） | 自动压入数据栈 | ✅ 继续 |
| 程序栈弹出**列表** | 反转后压入程序栈（正常流程） | ✅ 继续 |
| 程序栈弹出**操作ID** | 执行操作（正常流程） | ✅ 继续 |
| 操作执行时参数不足 | 触发事故，清空双栈 | ❌ 终止 |
| 操作执行时类型不匹配 | 触发事故，清空双栈 | ❌ 终止 |
| 操作执行时能量不足 | 触发事故，清空双栈 | ❌ 终止 |
| 操作执行时目标无效 | 触发事故，清空双栈 | ❌ 终止 |
| 运行时错误 (如除零) | 触发事故，清空双栈 | ❌ 终止 |
| 数据栈超出大小限制（如1024） | 触发事故，清空双栈 | ❌ 终止 |
| 程序栈超出大小限制（如1024） | 触发事故，清空双栈 | ❌ 终止 |

## 九、玩家使用流程

```
1. 获取外壳（方块/实体/工具形态）

2. 右键外壳 GUI
   ├── 放入运算核心（可多个）
   ├── 放入法术磁盘（存储程序）
   ├── 放入世界交互器（可选）
   └── 放入能量模块

3. 编写程序（栈图编辑器）
   ├── 可视化编辑操作序列（列表）
   ├── 编辑器实时类型推导
   ├── 使用 push + eval + 自复制实现循环
   └── 使用 send/recv 与超算通信

4. 使用成品
   ├── 工具：手持/饰品 → 自动激活
   ├── 方块：放置世界 → 区块加载运行
   └── 实体：右键召唤 → 存在时运行
```

## 十、设计原则总结

| 原则 | 说明 |
|------|------|
| 操作是一级公民 | 操作可组合、传递、动态执行 |
| 双栈执行 | 程序栈存可执行单元，数据栈存值 |
| 永续运行 | 程序持续执行直到栈空或显式停止 |
| 无原生循环 | 通过 `eval` + 自引用列表实现 |
| 非阻塞通信 | `recv` 返回 `null` 让玩家控制流 |
| 廉价通信 | 跨维度、低消耗 |
| 无强制限制 | 所有操作本地可执行（只是慢） |
| 开放扩展 | 任何模组可注册操作 |
| 类型安全 | 操作签名支持编辑器提示 |
| 物理决定逻辑 | 核心相邻合并，空间影响性能 |
| 反转压入 | 保证程序列表从左到右的执行顺序 |
| 数据宽容 | 程序栈中的数据自动压入数据栈 |
| 其余严格 | 其他所有错误触发事故并终止 |
