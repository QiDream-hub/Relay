## 二、模块划分

### 模块1：外壳管理器

**职责**：管理所有外壳的创建、销毁、合并、调度。

**核心组件**：
- `ShellRegistry`：注册外壳类型（方块、实体、工具）
- `CoreGroup`：处理相邻核心合并逻辑（无核心数上限，原版64，其他mod可扩展）
- `EnergySystem`：能量消耗与预检
- `Scheduler`：按 interval 调度状态机执行

**主要流程**：
```
外壳放置 → 读取磁盘 → 初始化状态机 → 注册到调度器
每个 Tick → 调度器检查 interval → 调用状态机执行
核心变化（放置/破坏）→ 重新计算核心组 → 更新操作数预算
```

---

### 模块2：状态机执行器

**职责**：维护双栈，执行操作，处理持久化。

**核心数据结构**：
- `programStack`：Deque<Iota>
- `dataStack`：Deque<Iota>
- `disk`：引用法术磁盘（用于重新加载）
- `remainingOps`：当前 Tick 剩余操作数
- `worldInteractor`：布尔标志

**栈大小限制**：
- 默认 1024
- 可通过配置文件修改

**持久化粒度**：
- 每次 Tick 操作数耗尽时保存状态（程序栈 + 数据栈）

**主要方法**：
- `loadProgram(disk)`：反转后压入程序栈
- `tick()`：执行循环
- `saveState()`：序列化双栈
- `restoreState(tag)`：反序列化

**执行循环伪代码**：
```
tick():
    remainingOps = getCoreCount()
    while remainingOps > 0 and programStack not empty:
        top = programStack.pop()
        if top is OperationID:
            callback = OperationRegistry.get(top)
            callback.execute(this)
            remainingOps -= 1
        elif top is List:
            reversedList = reverse(top.asList())
            for item in reversedList:
                programStack.push(item)
            remainingOps -= 1
        elif top is Data:
            dataStack.push(top)
            remainingOps -= 1
        else:
            triggerMishap("未知栈顶类型")
    if remainingOps == 0:
        saveState()
```

### 模块3：操作注册表

**职责**：操作ID与回调函数的绑定，提供类型签名供编辑器使用。

**核心数据结构**：
- `Map<String, OperationEntry>`：操作ID → 操作条目
- `OperationEntry`：包含回调、类型签名、消耗、权限标记

**注册方式**：
```
模组初始化时：
OperationRegistry.register("minecraft:add", AddOperation::new)
    .signature(INTEGER, INTEGER, INTEGER)
    .cost(1)
    .requiresWorldInteractor(false)  // 是否需要世界交互器
```

**回调接口**：
```
interface StackOperation {
    void execute(SpellExecutor executor);
    // 可选：默认消耗1，默认签名ANY，默认不需要世界交互器
}
```

**世界交互器检查**：
- 操作执行前检查 `requiresWorldInteractor`
- 如果为 true 且 `executor.worldInteractor == false`，触发事故

---

### 模块4：通信系统

**职责**：跨外壳、跨维度的消息传递。

**核心数据结构**：
- `Map<Integer, Queue<Iota>> channels`：频道号 → 消息队列
- 队列容量限制：1000（超出触发事故）
- 跨维度：全局静态 Map（所有维度共享）

**频道数量**：
- 不设上限（玩家自行管理）
- 大量频道可能影响性能，但在合理范围内

**操作实现**：
- `send(channel, data)`：队列未满则入队，返回 true；否则触发事故
- `recv(channel)`：队列非空则出队，否则返回 null
- `peek(channel)`：队列非空则查看头部，否则返回 null

**跨维度支持**：
- 直接支持所有维度
- 使用全局 Map，消息在所有维度间共享
- 类似现实中的无线电：只要频率对，就能收到

---

### 模块5：栈图编辑器

**职责**：让玩家可视化编写程序。

**核心功能**：
- 操作列表展示（可用操作从服务端获取）
- 拖拽式添加操作
- 实时类型推导（基于操作签名模拟栈变化）
- 错误标记（操作不存在、类型不匹配）
- 程序保存（发送到服务端，写入法术磁盘）

**编辑器API**：
- `GET /operations`：获取所有操作及其签名
- `POST /validate`：验证程序，返回类型推导结果和错误
- `POST /save`：保存程序到磁盘

## 三、设计原则（奥卡姆剃刀）

| 模块 | 简化点 |
|------|--------|
| 外壳管理器 | 无核心数上限，不引入额外限制 |
| 状态机 | 仅双栈 + 计数器，无PC、无调用栈 |
| 操作注册 | 最小接口（仅 execute 方法必需） |
| 通信系统 | 全局Map，无连接管理、无权限 |
| 栈大小 | 默认1024，可配置（不强制） |
| 持久化 | 仅保存双栈，无其他状态 |
| 跨维度 | 直接共享队列，无路由逻辑 |
| 世界交互器 | 简单布尔检查，无复杂权限 |

## 四、配置项

```properties
# 栈大小限制（默认1024）
stack.program.max=1024
stack.data.max=1024

# 频道队列容量（默认1000）
channel.queue.max=1000

# 操作数预算（默认64，由核心数决定，无独立配置）

# 持久化（默认启用）
persistence.enabled=true
```

## 五、实现优先级

### 第一阶段（核心原型）
1. 操作注册表
2. 状态机执行器（基础操作：push、add、sub、dup、swap、pop、eval）
3. 外壳（方块形态）+ 运算核心 + 能量模块
4. 基础通信（send/recv/peek，同维度）

### 第二阶段（完整功能）
1. 完整操作集（if、列表操作、世界交互）
2. 法术磁盘 + 程序加载/保存
3. 核心合并机制
4. 跨维度通信

### 第三阶段（用户体验）
1. 栈图编辑器（基础版本）
2. 类型推导与实时验证
3. 调试工具（单步执行、栈监视）
4. 示例程序库

## 六、与概念设计的对应

| 概念设计条目 | 框架实现 |
|-------------|----------|
| 双栈模型 | 状态机执行器中的 programStack / dataStack |
| 程序加载反转 | loadProgram 方法中的反转逻辑 |
| 执行循环 | tick 方法中的 while 循环 |
| 数据宽容 | 遇到 Data 时压入 dataStack |
| 列表展开 | 遇到 List 时反转后压入 programStack |
| 操作数预算 | getCoreCount() 提供，remainingOps 递减 |
| 程序栈空终止 | while 条件中检查 programStack 是否为空 |
| 持久化 | saveState / restoreState 在操作数耗尽时调用 |
| 通信 | 通信系统中的频道队列 |
| 世界交互器 | 操作回调中的 requiresWorldInteractor 检查 |
| 错误处理 | triggerMishap 清空双栈并终止 |
