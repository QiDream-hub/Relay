# Relay 模组实现列表

**文档目的**：将实现任务按"是否需要修改 MC 原版"分为两大类，指导开发优先级和工作分解。

**最后更新**：2026-05-29

---

## 一、无需修改 MC 原版（纯模组代码实现）

### 1.1 核心系统

#### 操作注册表 (Operation Registry)
- [ ] 数据结构：`Map<String, OperationEntry>`
- [ ] 操作条目：回调函数、类型签名、消耗、权限标记
- [ ] 注册 API：`register(id, factory).signature(...).cost(...).requiresWorldInteractor(...)`
- [ ] 查询 API：`get(operationId)` 返回操作回调

#### 状态机执行器 (State Machine Executor)
- [ ] 双栈数据结构：`Deque<Iota> programStack`, `Deque<Iota> dataStack`
- [ ] 程序加载：从磁盘读取列表，反转后压入程序栈
- [ ] 执行循环 (tick)：
  - 弹出栈顶元素
  - 操作 ID → 执行回调
  - 列表 → 反转后压入程序栈
  - 数据 → 自动压入数据栈（宽容规则）
- [ ] 事故处理：`triggerMishap()` 清空双栈并终止
- [ ] 持久化：`saveState()` / `restoreState()` 序列化双栈到 NBT

#### 通信系统 (Communication System)
- [ ] 频道管理：`Map<Integer, Queue<Iota>> channels`
- [ ] 队列容量限制：1000（超出触发事故）
- [ ] 操作实现：
  - `send(channel, data)`：入队，返回 true/失败
  - `recv(channel)`：出队或返回 null
  - `peek(channel)`：查看头部或返回 null
- [ ] 跨维度支持：全局静态 Map，所有维度共享

---

### 1.2 物品与方块

#### 运算核心
- [ ] 物品定义：`ComputingCoreItem`
- [ ] 属性：`interval`（1~100 可调）
- [ ] 相邻检测：放置时扫描相邻 6 面，合并核心组
- [ ] 核心组计算：总核心数累加，`interval = max(所有核心)`

#### 法术磁盘
- [ ] 物品定义：`SpellDiskItem`
- [ ] 数据存储：NBT 标签存储程序列表（Iota 序列）
- [ ] GUI 集成：外壳界面显示当前磁盘程序

#### 能量模块
- [ ] 物品定义：`EnergyModuleItem`
- [ ] 能量存储：内部缓存紫水晶能量
- [ ] 读取顺序：优先能量模块，其次外壳持有者背包

#### 外壳（方块形态）
- [ ] 方块定义：`ShellBlock`
- [ ] 方块实体绑定：`ShellBlockEntity`
- [ ] GUI 容器：4 个插槽（核心×N、磁盘、能量模块、世界交互器）
- [ ] 状态机绑定：每个外壳实例维护独立状态机

---

### 1.3 基础操作库

#### 栈操作
- [ ] `push(value)`：压入数据到数据栈
- [ ] `pop()`：弹出数据栈顶部
- [ ] `dup()`：复制数据栈顶部
- [ ] `swap()`：交换数据栈顶部两个元素

#### 算术操作
- [ ] `add`：弹出两个数值，压入和
- [ ] `sub`：弹出两个数值，压入差
- [ ] `mul`：弹出两个数值，压入积
- [ ] `div`：弹出两个数值，压入商（除零触发事故）

#### 比较操作
- [ ] `eq`：弹出两个值，判断相等，压入布尔
- [ ] `lt`：弹出两个数值，判断小于，压入布尔
- [ ] `gt`：弹出两个数值，判断大于，压入布尔

#### 逻辑操作
- [ ] `and`：弹出两个布尔，压入与结果
- [ ] `or`：弹出两个布尔，压入或结果
- [ ] `not`：弹出一个布尔，压入非结果

#### 控制流
- [ ] `eval`：弹出列表，反转后压入程序栈
- [ ] `if`：弹出条件 + 真分支 + 假分支，根据条件压入其中一个分支

#### 通信操作
- [ ] `send`：弹出频道号 + 数据，发送到频道
- [ ] `recv`：弹出频道号，接收数据或 null
- [ ] `peek`：弹出频道号，窥探数据或 null

---

### 1.4 客户端工具

#### 栈图编辑器 GUI
- [ ] 操作列表面板：展示可用操作（从服务端获取）
- [ ] 程序编辑区：拖拽式添加/删除/重排操作
- [ ] 实时类型推导：基于操作签名模拟栈变化
- [ ] 错误标记：操作不存在、类型不匹配时高亮
- [ ] 保存功能：发送程序到服务端，写入法术磁盘

#### 类型推导引擎
- [ ] 操作签名解析：输入类型 → 输出类型
- [ ] 栈状态模拟：逐个操作推导栈变化
- [ ] 错误检测：参数不足、类型不匹配时标记

---

### 2.5 网络与同步

#### 网络包处理
- [ ] 客户端 → 服务端：
  - `C2S_UpdateProgram`：更新法术磁盘程序
  - `C2S_RequestOperations`：请求可用操作列表
- [ ] 服务端 → 客户端：
  - `S2C_SyncState`：同步外壳状态（双栈内容、能量）
  - `S2C_OperationList`：返回操作注册表

#### 编辑器 API 端点（可选，用于外部工具）
- [ ] `GET /operations`：获取所有操作及签名
- [ ] `POST /validate`：验证程序，返回类型推导结果和错误
- [ ] `POST /save`：保存程序到指定磁盘

## 三、实现优先级与阶段

### 第一阶段：核心原型（2-3 周）
**目标**：可运行的最小可用版本

| 任务 | 优先级 | 依赖 |
|------|--------|------|
| 操作注册表 | P0 | 无 |
| 状态机执行器（基础循环） | P0 | 操作注册表 |
| 基础操作（push, add, dup, eval） | P0 | 操作注册表 |
| 外壳方块 + 方块实体 | P0 | 状态机 |
| 运算核心物品 | P1 | 外壳 |

**验收标准**：放置外壳 + 核心，执行 1+1 计算，结果保留在数据栈。

---

### 第二阶段：完整功能（3-4 周）
**目标**：支持完整编程能力

| 任务 | 优先级 | 依赖 |
|------|--------|------|
| 法术磁盘 + 程序加载/保存 | P0 | 外壳 |
| 核心合并机制 | P1 | 运算核心 |
| 能量系统 | P1 | 外壳 |
| 通信系统（同维度） | P1 | 状态机 |
| 完整操作库（if, 列表操作，比较，逻辑） | P1 | 状态机 |
| 跨维度通信 | P2 | 通信系统 |

**验收标准**：编写自复制循环程序，跨外壳通信，核心相邻合并增强算力。

---

### 第三阶段：用户体验（3-4 周）
**目标**：降低玩家使用门槛

| 任务 | 优先级 | 依赖 |
|------|--------|------|
| 栈图编辑器（基础版本） | P0 | 操作注册表 |
| 类型推导与实时验证 | P1 | 编辑器 |
| GUI 容器与物品插槽 | P0 | 外壳 |
| 调试工具（单步执行、栈监视） | P2 | 编辑器 |
| 示例程序库 | P2 | 完整操作库 |

**验收标准**：玩家可通过 GUI 可视化编程，实时看到类型推导结果。

---

### 第四阶段：扩展形态（2-3 周）
**目标**：支持多种外壳形态

| 任务 | 优先级 | 依赖 |
|------|--------|------|
| 世界交互器物品 | P0 | 外壳 |
| 世界交互操作库 | P0 | 世界交互器 |
| 外壳实体形态 | P1 | 状态机 |
| 工具形态（手持/饰品） | P2 | 状态机 |

**验收标准**：外壳可放置方块、与实体交互，实体形态持续运行。

## 四、风险与注意事项

| 风险点 | 影响 | 缓解措施 |
|--------|------|----------|
| 状态机性能 | 大量外壳同时运行可能卡顿 | 限制每 Tick 操作数，支持配置 |
| 网络同步延迟 | 编辑器保存程序时可能丢包 | 添加确认机制，失败重试 |
| 核心合并边界情况 | 复杂布局可能计算错误 | 编写单元测试覆盖所有相邻情况 |
| 持久化兼容性 | 版本升级后 NBT 格式变化 | 添加版本字段，支持迁移 |
| 跨维度通信线程安全 | 多线程访问频道 Map | 使用 ConcurrentHashMap 或同步锁 |
